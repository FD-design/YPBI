# UI 已确认问题与防回归规则

本文件是 YPBI 已确认 UI/交互问题的长期权威记录。它不复制设计 Token，也不保存主观评审过程；只记录已经复现的问题、根因、强制实现规则和验收方法。视觉数值仍以 `src/theme/tokens.css` 为准，页面现状以代码为准。

## 使用规则

1. 任何 UI、交互、响应式、弹层或工作区布局修改，开始前必须阅读本文件。
2. 已登记问题不得通过局部补丁绕开；必须在唯一组件、Hook 或 Token 层修复全部同类位置。
3. 再次出现的问题沿用原 ID 更新影响面和防回归用例，不新建同义条目。
4. 新确认的问题必须登记：现象、根因、强制规则、影响面、自动/人工验收方法和当前状态。
5. 已修复条目永久保留；状态改为“已修复并设防”，不得删除历史护栏。

## 功能与 UI 边界

- 模块是否存在、入口名称、功能范围和业务流程，以最新[产品需求文档](./requirements/BI-产品需求文档.md)中相应章节的确认状态为准；本文件不能创建、保留或扩大任何产品功能。
- 清单中的“模板管理、数据字典、卡片编辑、完整预览、分析模型、保存并发布”等名称只标记问题发生时的历史影响面，不代表目标架构必须保留同名模块或流程。
- 目标架构已明确迁移时，防回归规则跟随目标对象继续生效：模板管理归入看板自身编辑，数据字典拆入指标中心/事件中心，查询编辑归入来源分析；公共看板按 PRD 直接保存，不因旧条目恢复发布流程。
- 回归只覆盖当前仍存在的路径和 PRD 已确认建设的目标路径。某模块尚不存在或尚未确认时，不得为了满足本文件而新增入口、页面、字段或动作。
- 产品功能冲突时先按 PRD 收口功能，再把仍适用的布局、响应式、弹层、控件和状态护栏映射到新路径；不得让旧 UI 实现反向决定产品结构。

## 新界面通用准入引用

本文件不复制新界面的通用产品行为或工程检查清单。目标页面的导航、草稿、异步状态、多端和可访问性以[产品需求文档第 4.3 节](./requirements/BI-产品需求文档.md)为准；受影响状态、边界数据、视口、键盘主链和真实浏览器验证以项目根目录 `AGENTS.md` 第 9 节为准。本文件以下条目只约束已经复现的 UI 根因及仍适用于当前路径的专项回归。

## UI 修改最低回归清单

以下是对“当前存在或已确认目标路径”的条件清单，不是产品模块清单；已取消或尚未确认的模块不得因此被新增或保留。

- 看板中心：模板切换、平台筛选、日期筛选、保存筛选、卡片视图切换、完整预览和下钻。
- 分析中心：搜索、自定义模型筛选、桌面分类完整换行、手机分类横向滑动、卡片操作和紧凑预览防溢出。
- 分析创建器：模型横向列表、字段选择、漏斗步骤、实时预览、撤销和保存。
- 模板管理：模板切换、添加卡片抽屉、卡片编辑抽屉、拖放、宽度调整、保存和发布。
- 数据字典、数据源维护：表单状态、主次按钮、禁用态和响应式布局。
- 视口：1280px、1024px、390px；每档检查横向溢出、点击光标和覆盖层打开前后布局。
- 自动化：`qa-ui-shell.spec.js` 至少覆盖经典版 SPA Shell、可点击光标、业务区无原生下拉、分类无截断、Portal 遮罩层级、筛选无位移、日期双分区与锚定位置、模板抽屉无位移、移动顶栏 sticky 和手机 Sheet 全宽；`qa-v2-shell.spec.js` 至少覆盖 V2 真实 0 / 无记录、图表与完整表、503 失败关闭、分析 URL 规范化后的刷新 / 返回，以及 390px modal 导航、焦点恢复和横向溢出。

执行目标架构改造后，上述旧路径按以下方式归并：看板/模板查看规则进入“看板中心”，模板管理和看板展示编辑进入“看板编辑”，卡片查询编辑和分析创建器进入对应“来源分析”，数据字典规则分别进入“指标中心/事件中心”，数据源维护进入“管理”。不存在的旧入口只验证已删除，不做功能回建。
