# UI 已确认问题与防回归规则

本文件是 YPBI 已确认 UI/交互问题的长期权威记录。它不复制设计 Token，也不保存主观评审过程；只记录已经复现的问题、根因、强制实现规则和验收方法。视觉数值仍以 `src/theme/tokens.css` 为准，页面现状以代码为准。

> 当前版本：1.42｜更新日期：2026-09-16

## 本轮共享根因与验收入口

UI-031/033：普通日卡投影先保留来源的失败和未成熟状态，再转换可用日值；共享主题卡分支同样经过状态判断，不通过重新生成演示值覆盖失败。末日无值按该日状态显示并保留其他日期趋势，日对比使用已确认的 D−1 / D−7；回归同时核对主值、日期、变化、历史趋势和单卡重试，不沿用周期摘要的旧文案断言。实现入口为 `extendedDailyMetricModel`、`dailyMetricReading`，回归见模型单测及获客、后续看板、核心样板浏览器用例。

内容发现按 PRD 5.13 的三个业务区连续排列；使用现有指标卡、分析和表格组件，摘要与对应明细同区。保留不同业务事实和完整数据能力，清理旧分散循环与重复层级。`ContentDiscoveryBoard` 与 `qa-v2-content-sections.spec.ts` 承载分区及保留项验收。

UI-035/040：计算详情保留来源公式、实名输入、原始单位和值；不得另行拼接省略单位换算的数字等式。秒换算分钟的公式保留除以 60，单输入时长保留秒转小时说明，不虚构人数分母。真实阶段读数、逐日详情和导出使用同一查询；混合来源逐指标标识，正常来源标签不重复。回归见计算表模型、`qa-v2-calculation-columns.spec.ts` 和 `qa-v2-playback-live.spec.ts`。

UI-035/040/041补充：详细图点击按系列语义识别当前/对比，不依赖绘图顺序；经营快照按PID与业务日绑定，日期切换不能把旧值标成新日；来源失败提供重试，不改成普通缺值。已接支付切片保留总体与分组计算依据和合法占比，留存率分母0仍保留有效人数0。混合收入模块的商品、端别、趋势和交叉表分别显示实际来源标签，Provider本身不替代可见标签；真实导出包含两期状态、平台、查询时间与刷新状态。演示来源卡不显示“已验数”等正式验收标签。验收样例见日看板模型测试及连接看板浏览器用例。

UI-005/008/015/041：公共/我的概览由同一工作台装配，切换只更换目录内容与当前看板，保留布局和历史；手机复用同一目录抽屉。留存热力图把全部日期挤入固定画布会产生不可读条纹，统一改为36px逐日行、内部滚动、固定表头和日期列，39/90/180日均保留完整结果及逐格值。公式在同口径表上方集中显示，每个周期定义只出现一次；人数、结果、窗口和状态仍逐行展示。

UI-020/021：本地XLSX下载在原生模态框中不得激活游离于活动弹窗之外的临时链接。共享下载器将链接挂载在当前非inert弹窗内再触发，完成激活后移除、延后释放Blob URL；必须实际下载并解析文件，不能仅检查导出弹窗关闭或按钮存在。`qa-v2-function-usage.spec.js`覆盖同口径表内嵌导出的完整文件与不受搜索裁剪的结果。

UI-020/021/040：下载文件名与内容采用同一来源状态，分别标明待验数、演示或来源分列；经营明细保留逐期计算输入。业务名称用作Excel工作表名时统一处理非法字符、31字符限制和不区分大小写的重名，并提供完整名称索引；原始业务名称及输入数据保持不变。共享生成器单元测试和连接看板实际下载覆盖整板多指标及原演示文件。

UI-035/041：`CalculationEvidence`紧凑态只保留一行计算入口，详情和完整表不省略实名输入。留存工具左侧选择、右侧放大/导出，图例留独立轴外空间；趋势不显示热力色阶，放大继承当前视图。比较维度始终由同一个完整选择器承载。

UI-040：演示值仅由显式DEV来源上下文标识，标题旁带“演示数据”；不通过数值是否为空猜测来源，不将正式错误回退为合成值。速览到分析需携带指标/平台/日期，查看定义需实际打开内容；回归必须点击验证目的页，不能只判断链接存在。

UI-008/041：详细卡内“趋势/表格”共用受控阅读高度和底部数据表入口，长日期按日期缩放区增加高度；表格主体内部滚动、分页保持可达。仅设min-height会被完整计算列撑高，必须验证切换前后卡片高度及相邻卡位置不变；完整大表继续由独立阅读窗口承载。`DetailedMetricTrend`与`qa-v2-reading.spec.js`覆盖这一失败样例。

实名计算输入统一由`CalculationEvidence`和`CalculationColumns`承载，当前期/对比期分别取自身快照；未知输入保留名字及待接入状态，不能由比率反推。`GroupedTrend`接收独立总体和原总体占比；总体不与子组一起堆叠。`RetentionMatrix`增加全日期热力概览、趋势、表格及放大，未成熟不补0。目标统一引用总PRD4.3、5.8～5.13；`qa-v2-review-feedback.spec.js`与`qa-v2-operations-redesign.spec.js`覆盖这些失败样例。

沿用UI-017/020/021：只读模态共用`useDialogBackdrop`，仅同次指针按下和松开均在遮罩时关闭，内部拖动到外部不关闭；Esc、关闭按钮、滚动锁和焦点返回保持。Token保存确认允许取消并保留候选输入，忙碌期间不关闭。输入Token与正式身份、连接探针、指标验数状态分别验证；`qa-v2-data-sources.spec.js`使用隔离凭证和响应，不记录真实Token。

UI-036/041 的 2.27 护栏：比率与实名输入就近阅读，公式统一展开；总体与位置、当前与对比、图表与导出共用同一结果投影，不平均比率或由率倒推基数。图形 TopN 在用户所选排序之后截取，不能覆盖“业务顺序”；完整表与导出保留全集。紧凑卡保留原逐日详情与导出入口，不因隐藏大图丢失阅读能力。版本使用“客户端＋应用版本”联合实体，新老用户是同指标维度，M020 / M024 按自身批次显示。导航使用放在功能页独立区，不混入页面目录或导航广告。网络展示退出只影响指定两看板；相邻事件分析和连接异常必须保留。以上规则复用既有表格、MetricBreakdown、CalculationEvidence 和数据状态组件；本批真实数据边界见数据支持清单。

## 使用规则

紧凑卡的工具区按实际内容宽度布局，不能继续固定为单个说明图标的 24px 列；增加完整趋势入口后须实际点击放大与说明，验证两个按钮互不覆盖。紧凑摘要保留折线 / 柱状 / 表格完整阅读、逐日输入、下载和关闭焦点恢复。业务主辅网格使用明确组件选择器，须断言最终主辅列宽，不能只检查样式源码中存在比例声明。

专题本地视图写入URL与真正导航分开：工作台仅在显式路由跳转或浏览器历史前进/后退时重建结果组件，记录日期和阅读视图不触发重建。不得使用会随本地`replaceState`变化的URL作为结果树key；回归须在应用日期后选留存人数或图形指标，再跨1280/1024/390宽度，验证选择、数据和分页仍保留，历史导航仍按目标视图还原。深色漏斗填充内的文字显式使用高对比浅色，实际截图确认，不依赖默认标签色。

新增阅读规则已进入本地回归。纯数值卡沿用UI-040，只读弹层沿用UI-017/041，目标引用总PRD15.4；共享入口为`DashboardMetricCard`、`MetricBreakdown`、`MetricReadingDialog`。`qa-v2-operating-detail.spec.js`与`qa-v2-analysis-rebuild.spec.js`覆盖维度提示、整卡/释义独立命中、紧凑高度、缺失/未成熟、只读遮罩关闭、内部拖动、焦点恢复和编辑草稿退出保护。只读与编辑关闭策略显式分离，不能因复用组件丢弃编辑数据。

## UI 修改最低回归清单

以下是对“当前存在或已确认目标路径”的条件清单，不是产品模块清单；已取消或尚未确认的模块不得因此被新增或保留。

- 看板中心：模板切换、平台筛选、日期筛选、保存筛选、卡片视图切换、完整预览和下钻。
- 分析中心：搜索、自定义模型筛选、桌面分类完整换行、手机分类横向滑动、卡片操作和紧凑预览防溢出。
- 分析创建器：模型横向列表、字段选择、漏斗步骤、实时预览、撤销和保存。
- 模板管理：模板切换、添加卡片抽屉、卡片编辑抽屉、拖放、宽度调整、保存和发布。
- 数据字典、数据源维护：表单状态、主次按钮、禁用态和响应式布局。
- 视口：1280px、1024px、390px；每档检查横向溢出、点击光标和覆盖层打开前后布局。
- 自动化：`qa-ui-shell.spec.js` 至少覆盖经典版 SPA Shell、可点击光标、业务区无原生下拉、分类无截断、Portal 遮罩层级、筛选无位移、日期双分区与锚定位置、模板抽屉无位移、移动顶栏 sticky 和手机 Sheet 全宽；`qa-v2-shell.spec.js` 至少覆盖 V2 真实 0 / 无记录、图表与完整表、503 失败关闭、分析 URL 规范化后的刷新 / 返回、`MenuSelect` 的上下循环 / `Home / End` / 选择与 Esc 焦点返回，以及核心经营总览开发样板在 1280 / 1024 / 390 下的正常态、组合异常态、移动操作收纳和横向经营表。生产构建还必须确认不包含样板组件、样板 CSS 或固定演示文案。
