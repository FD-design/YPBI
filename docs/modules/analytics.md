# 分析引擎模块

## 2026-09-10 分析页本地交互层

指标分析、事件分析、漏斗分析及已保存分析的本地页面共用`PersonalWorkspacePreview`。DEV事件过滤/聚合、展示兼容及有序漏斗分别由`event-analysis-preview.ts`、`analysis-presentation.ts`、`funnel-analysis-preview.ts`负责。合成事实具有固定主体与唯一键，区间UV和漏斗步骤由事实计算，不累计日人数或拼接阶段汇总。它们不调用下方遗留分析，也不代表正式执行器。配置内存保存、结果快照与导出保持分离；正式查询、身份、关联与对象写入的剩余范围以调整方案9.11为准。

## 2026-09-08 V2 当前分析切片

新版首批只读指标链路不复用本文件下方的旧模型注册、浏览器两次查询拼比较、缺失补 0、阶段汇总漏斗或前端导出逻辑。它通过 `contracts/bi-v2.ts → server/v2/plugin.ts → V2MetricQueryService → M016Source` 独立执行，该正式指标查询切片仅支持 M016 单 PID 日序列；本地日看板读取由独立服务承载，不改变该切片准入，并端到端保留真实 0、无记录、空值、待验数和未知水位。

正式V2尚未开放指标比较、事件分析、漏斗分析、保存、导出或自动诊断；本地页面体验见上节，不能替代正式准入。M016 仍是“技术称已实现（待验数）”，不能据此标记为可正式使用。

## 遗留分析引擎当前事实（仅迁移与回退核对）

本节及其全部子章节只记录旧 `/api/bi/analytics*` 与旧前端仍可执行的实现事实，不是目标功能清单，也不是指标、公式、事件或数据状态的第二权威源。目标产品范围以[总 PRD](../requirements/BI-产品需求文档.md)为准，当前差距与迁移顺序以[现有平台调整方案](../requirements/BI-现有平台调整方案.md)为准，指标和事件定义只引用外部权威文档的稳定 ID 与版本。

旧实现中的固定 20 平台、缺失平台补 0、用总量相减派生老用户、把阶段汇总列包装成漏斗，均为已知偏差，禁止迁入 V2；必须按调整方案替换或退役。任何旧模型、指标、聚合或图表能力进入 V2 前，都必须重新绑定权威 ID / 版本、声明能力、通过查询与验数，并按总 PRD 的数据状态契约返回，不得因旧代码“可算”就自动准入。

### 2026-08-03 遗留周期对比计算

- `calendarMonth`：以上一完整自然月为对比周期，不强制与当前月天数一致。
- `equalLength`：对比周期为当前开始日前紧邻的等长日期范围。
- `sameProgress`：对比周期为上月 1 日至当前结束日的相同日序；遇到短月时取上月最后一天。
- 两个周期仍分别发起真实 API 查询；涨跌值由相同指标当前结果与对比结果计算。

### 2026-08-03 遗留时间聚合实现审计（非指标口径权威）

旧引擎本地注册了日均、累计人天、区间求和、加权比例和周期末快照等聚合分支，也曾修复将日 UV 跨天直接求和的问题；精确计算仍由遗留代码与测试描述。本文件不再复制这些公式或把旧本地指标 ID 当成目标口径，V2 必须按外部指标权威源的 ID、版本和状态重新接入。

遗留引擎不具备周期用户级去重所需的稳定用户 ID；相关旧结果不能改名后迁入 V2。

16 项是旧创建器兼容上限，不是 V1 产品入口或目标上限。V1 指标分析按总 PRD 的已确认规则默认 1 项、最多 5 项；旧 16 项能力不得直接暴露给 V2。

### 2026-07-23 遗留获客转化模型

- 旧 `/api/bi/analytics/query` 已存在 `acquisition_conversion` 模型，能从 `/api/admin/statistics/cpGuardStat/cnzzstatQuery` 与 `/api/admin/statistics/pDaySum` 组合返回访问、下载、新增注册及三段转化候选结果。

- CNZZ 未返回记录时保留空结果，不把缺失记录伪装为 0；当前期无记录时同期比较不展示虚假 `-100%`。

- 旧引擎曾将 `payerCount` 暴露为可配置字段，候选来源为 `totalChargeUserCount`；这不等于目标指标已准入。
- 带时区的上游统计日期统一换算为北京时间自然日，避免 `2026-06-22` 被显示为前一天。

这里的“已接入”只指遗留组合查询可执行，不代表 M001、M003、M005～M008 等目标指标已完成权威映射、权限接入或验数。获客指标进入 V2 前仍须逐项完成这些工作。

### 遗留查询流程

1. 前端卡片生成 `AnalyticsQuery`。
2. Zod 校验分析类型、平台数量、日期和字段数量。
3. 能力校验器检查指标、维度、漏斗事件组合。
4. QueryOrchestrator 选择对应 Adapter。
5. 多平台查询按受控并发执行。
6. 服务端完成求和、加权比例、漏斗重算和部分失败汇总。
7. 前端将标准结果转换为 KPI、折线、柱状、散点、热力、漏斗、Cohort、瀑布、贡献矩形、汇总桑基或表格。

### 遗留图表计算能力

- 热力图：使用真实 `platform × date × metric` 行生成二维矩阵；没有页面和坑位字段时不伪造页面坑位热力图。
- 瀑布图：按平台、内容、分类或搜索词累加首个指标，展示各维度贡献及合计。
- 贡献矩形图：按平台或“分类 → 内容”聚合首个指标，面积表示真实汇总贡献。
- 汇总桑基图：复用固定事件漏斗查询，把相邻阶段汇总量连接为流量图；它是阶段损耗可视化，不代表同一用户的真实有序路径。
- 散点和诊断：由真实结果行继续计算规模效率位置和平台差异。
- 上述派生图仅改变前端展示转换，不修改上游接口，也不生成 Mock 数据。
- 查询协议要求显式传入 `modelId`；服务端按模型再次校验指标、维度和漏斗事件，拒绝“搜索模型 + 付费指标”等错配请求。
- 图表展示类型与后端分析类型分开映射，但请求保留卡片配置的真实维度，例如 `category/content/keyword`，不依赖 Adapter 忽略维度才能运行。

散点、热力、瀑布、贡献矩形和桑基等只属于旧渲染能力，不是 V1 通用高级图表入口。V1 只开放总 PRD 明确列出的图表与适配组合；其余能力即使旧代码可渲染，也不得在 V2 暴露。

### 遗留前端查询可观测性

- 每张卡片在查询开始、成功、失败和取消时派发统一 `bi-query-status` 事件。
- 页面顶部聚合当前加载数、异常数、最近成功时间和卡片耗时。
- 查询失败时保留上一次成功结果；用户可在卡片内单独重试。
- 可观测状态只反映 BI 查询链路，不修改或探测上游后台接口配置。

`bi-query-status` 只是旧前端内部的技术协调信号，不是产品埋点，不进入事件中心，也不能替代总 PRD 中的产品成功指标与埋点验收。旧“保留上次成功结果”也不代表目标三层状态已满足；V2 必须把服务端对象、页面查询、表单/编辑草稿分别管理，旧结果标明实际查询时间与刷新失败/过期状态，并在查询条件或草稿改变后禁止把它当作新结果导出或加入看板。

### 遗留自动诊断

- 诊断卡基于当前真实平台行计算活跃规模最高、观影率最低和付费率最低的平台。
- 只有接口实际返回数值的指标才参与比较；缺失值不会按 `0` 参与排序。
- 没有对比周期数据时只展示当前筛选区间，不生成伪环比结论。
- 技术字段和上游告警不会直接伪装成业务分析结论。
- 图表节点下钻根据当前节点值与图表节点均值生成真实比较结论，并保留真实业务明细入口。

自动诊断没有进入 V1 范围，也没有可迁移的权威方向、阈值和解释契约；V2 不展示该入口或自动生成诊断结论。

### 遗留分析类型

- `metric`：汇总指标。
- `trend`：按日期或时点趋势。
- `ranking`：平台、内容或搜索词排行。
- `table`：结构化统计表。
- `funnel`：固定开放事件的汇总漏斗。
- `retention`：注册 Cohort 留存。

### 遗留本地指标注册（非指标口径权威）

旧 `server/analytics/registry.ts` 维护了一批本地字段别名和聚合规则，覆盖活跃、新增、观看、广告、付费、留存和来源拆分；这些内容只用于解释遗留查询为何仍能执行。本文件不维护其公式，目标定义、分子分母、聚合方式、单位和状态只来自外部指标权威源，V2 通过稳定指标 ID 与版本引用。

遗留实现已知存在接口候选字段、旧派生规则和未验数结果，不能因为旧页面显示出数就升级为“已接入”或“已验数”。

### 遗留运营日报接入边界

- 旧引擎曾从 `/api/admin/statistics/pDaySum` 注册 22 个可配置字段或同一行计算结果；这是遗留能力数量，不是 V1 指标清单。
- 历史日期 MAU 在旧接口中没有已确认稳定字段，遗留日汇总不开放替代值。
- 旧 `acquisition_conversion` 组合查询已经能读取 CNZZ 与 `pDaySum` 候选数据；但 `pDaySum/getAllByRole` 单一来源本身不包含访问、下载、注册转化的全部字段，且目标获客指标尚未完成 V2 权威映射与验数。支付宝/微信拉单拆分同样须逐项接入，正式看板不得生成替代值。

### 遗留多平台规则与已知偏差

- 旧全部汇总遍历当前注册表中的 20 个 PID；20 只是当时代码集合，不是业务上限。
- 单平台：只请求一个 PID。
- 平台对比：最多 8 个 PID。
- 普通趋势和排行保留平台字段。
- 对比图为每个平台生成独立系列。
- 单个平台失败时保留其他平台结果，并在 `failedPlatforms` 中返回失败信息。
- 旧全部平台模式把注册表固定为 20 个平台，并把接口未返回的平台补成占位 `0`。这是已知错误语义，不得迁入 V2；V2 平台范围必须由服务端目录与身份范围动态返回，未返回、无值和真实 0 分开表达。
- 平台排行、趋势、散点、日期热力、Cohort、瀑布和贡献矩形均保留所选范围内全部平台，不在转换层执行 Top N 截断。
- Cohort 使用“平台 × 注册日期”矩阵；平台趋势为每个平台生成独立日期系列。
- 搜索、内容等含二级业务维度的数据在卡片选择“平台”维度时，必须按 `platform` 聚合，不能用 `keyword/content/category` 替代平台轴。
- 分类、渠道和专项专用模板由前端按所选 PID 分别调用已有接口，再按对应业务维度汇总；页面范围必须与顶部筛选一致。

### 遗留日期范围规则

- 快捷范围支持今日、近 7 日和近 30 日。
- 自定义范围使用 `YYYY-MM-DD` 起止日期，查询包含开始与结束当天。
- 全部通用卡片、下钻、渠道、内容分类和专项分析共用同一日期解析函数，避免页面口径不一致。
- 通用卡片分别请求当前周期和等长对比周期；未手动指定时，对比周期自动取当前周期之前紧邻的等长日期。
- 旧变化率计算在对比值为零或缺失时不生成数值；目标公式与展示规则仍以总 PRD 和指标权威源为准。

### 遗留阶段汇总“漏斗”（不可迁为 V2 漏斗）

该实现只有独立事件的阶段汇总列，不具备用户级身份归一、有序步骤或转化窗口，因此不是目标漏斗；不得把旧列或汇总桑基直接迁入 V2。

- 内容漏斗：活跃用户、视频点击、视频播放、播放完成。
- 支付漏斗：VIP 点击、拉起支付、支付成功（内部事件 ID 仍为 `pre_pay`）。
- 当前数据来自同一日期区间的事件汇总计数。
- 不能证明同一批用户按顺序完成步骤。
- 当后一步独立事件量大于前一步时，标记为“事件口径不可比”，总转化率和步骤转化率显示“—”，不得展示超过 100% 的伪漏斗结论。
- 不支持用户级去重、任意转化窗口、页面/坑位/内容属性拆分。
- 桑基图与漏斗共用同一固定事件白名单和日期范围，必须明确标注“汇总近似，非用户级路径”。

### 遗留视频内容接入边界

- 视频内容表现使用 `/api/admin/statistics/videoWatchRanking`，按平台筛选视频播放、点赞、收藏和收入。
- `/api/admin/statistics/todayVideos/getMany` 在当前后台返回旧平台 PID，不能作为现有 20 平台内容卡片的数据源。
- 视频排行接口没有观看人数和平均观看时长，因此这两项不在内容表现模型开放；人均观影时长继续由“观看深度”模型调用实时接口计算。
- 视频排行接口当前收入字段长期返回 0，因此系统内容模板默认只展示播放、点赞和收藏；收入字段仍保留在受控配置能力中，待上游确认有效后再恢复为默认卡片。

### 遗留性能策略

- 上游 GET 请求相同 URL 并发合并。
- 成功响应在 BI 服务内存中缓存 60 秒。
- 缓存不写入数据库，服务重启后清空。
- 上游单请求默认 10 秒超时。
- 缓存只减少重复读取，不修改上游接口和数据。
- 前端对完全相同的分析请求共享 45 秒 Promise 缓存；失败立即清除，手动重试绕过缓存，单张卡片卸载不会取消其他共享请求。
- 平台排行通过动态高度展示全部平台；趋势图例可滚动，气泡矩阵仅限制常显标签数量但保留全部点位。
- 20 平台轴向 Tooltip 按值降序并使用双列完整列表，挂载到页面 `body`，避免被卡片裁切。
- 上游技术告警只进入查询诊断信息，不进入关键变化、主要原因等业务结论；业务结论仅由真实结果行计算。
### 2026-07-24 遗留老用户派生偏差（待清理）

旧引擎曾从总活跃、新增、总广告或总充值中以相减方式构造老用户及其广告、付费结果，并据此继续计算比例。这是无法证明同一对象和同一粒度的旧偏差，禁止迁入 V2，也不得作为目标指标公式；新老用户必须由权威指标或已验收维度直接返回。

该旧逻辑只读取 `/api/admin/statistics/pDaySum`，没有新增上游请求。保留本段仅用于定位并清理遗留实现。

### 遗留查询缓存内存边界

- 浏览器查询共享缓存有效期 45 秒，最多保留 200 条；写入前清理过期项并淘汰最早项。
- BI 后端上游响应缓存有效期 60 秒，最多保留 500 条；写入前清理过期项并淘汰最早项。
- 两层缓存都只保存在进程内存，不持久化业务查询结果。

### 2026-07-27 遗留 24 小时实时走势

- 使用 `/api/admin/home/pRealDayLine` 的 5 分钟时点数据，每日共 288 个点（00:00-23:55）。
- 新增登录用户、新增用户、观影用户三类 24 小时曲线。
- 当前线读取当前周期结束日，对比线读取对比周期结束日，横轴统一为 `HH:mm`。
- 支持单平台和最多 4 平台对比；每个平台独立成线，不跨平台去重或混算。
- 原始字段分别为 `loginUserCount`、`newUserCount/registerUserCount`、`watchUserCount`。
