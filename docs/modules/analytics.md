# 分析引擎模块

## 2026-08-03 周期对比计算

- `calendarMonth`：以上一完整自然月为对比周期，不强制与当前月天数一致。
- `equalLength`：对比周期为当前开始日前紧邻的等长日期范围。
- `sameProgress`：对比周期为上月 1 日至当前结束日的相同日序；遇到短月时取上月最后一天。
- 两个周期仍分别发起真实 API 查询；涨跌值由相同指标当前结果与对比结果计算。

## 2026-08-03 时间聚合口径审计

| 指标类型 | 多日默认口径 | 示例 |

- 带时区的上游统计日期统一换算为北京时间自然日，避免 `2026-06-22` 被显示为前一天。

## 查询流程

1. 前端卡片生成 `AnalyticsQuery`。
2. Zod 校验分析类型、平台数量、日期和字段数量。
3. 能力校验器检查指标、维度、漏斗事件组合。
4. QueryOrchestrator 选择对应 Adapter。
5. 多平台查询按受控并发执行。
6. 服务端完成求和、加权比例、漏斗重算和部分失败汇总。
7. 前端将标准结果转换为 KPI、折线、柱状、散点、热力、漏斗、Cohort、瀑布、贡献矩形、汇总桑基或表格。

## 图表计算能力

- 热力图：使用真实 `platform × date × metric` 行生成二维矩阵；没有页面和坑位字段时不伪造页面坑位热力图。
- 瀑布图：按平台、内容、分类或搜索词累加首个指标，展示各维度贡献及合计。
- 贡献矩形图：按平台或“分类 → 内容”聚合首个指标，面积表示真实汇总贡献。
- 汇总桑基图：复用固定事件漏斗查询，把相邻阶段汇总量连接为流量图；它是阶段损耗可视化，不代表同一用户的真实有序路径。
- 散点和诊断：由真实结果行继续计算规模效率位置和平台差异。
- 上述派生图仅改变前端展示转换，不修改上游接口，也不生成 Mock 数据。
- 查询协议要求显式传入 `modelId`；服务端按模型再次校验指标、维度和漏斗事件，拒绝“搜索模型 + 付费指标”等错配请求。
- 图表展示类型与后端分析类型分开映射，但请求保留卡片配置的真实维度，例如 `category/content/keyword`，不依赖 Adapter 忽略维度才能运行。

## 前端查询可观测性

- 每张卡片在查询开始、成功、失败和取消时派发统一 `bi-query-status` 事件。
- 页面顶部聚合当前加载数、异常数、最近成功时间和卡片耗时。
- 查询失败时保留上一次成功结果；用户可在卡片内单独重试。
- 可观测状态只反映 BI 查询链路，不修改或探测上游后台接口配置。

## 自动诊断

- 诊断卡基于当前真实平台行计算活跃规模最高、观影率最低和付费率最低的平台。
- 只有接口实际返回数值的指标才参与比较；缺失值不会按 `0` 参与排序。
- 没有对比周期数据时只展示当前筛选区间，不生成伪环比结论。
- 技术字段和上游告警不会直接伪装成业务分析结论。
- 图表节点下钻根据当前节点值与图表节点均值生成真实比较结论，并保留真实业务明细入口。

## 分析类型

- `metric`：汇总指标。
- `trend`：按日期或时点趋势。
- `ranking`：平台、内容或搜索词排行。
- `table`：结构化统计表。
- `funnel`：固定开放事件的汇总漏斗。
- `retention`：注册 Cohort 留存。

## 指标口径

- 数量和金额：求和。
- 观影率：`sum(viewerCount) / sum(dau)`。
- 付费率：`sum(payerCount) / sum(dau)`。
- ARPU：`sum(revenue) / sum(dau)`；ARPPU：`sum(revenue) / sum(payerCount)`。
- Android/IOS 活跃与新增：分别汇总后台对应端别字段。
- 自然新增与内部导量：直接汇总后台来源字段，不使用“总新增相减”推导。
- 广告点击人次率：`sum(totalClickedCount) / sum(dau)`；广告点击人数率使用 `totalClickedPerson` 作为分子。
- 新增广告点击两项比例以 `registerUserCount` 为统一分母。
- 新增付费率：`sum(newUserChargeUserCount) / sum(registerUserCount)`。
- 新增 ARPU/ARPPU：新增充值金额分别除以新增人数、新增付费人数。
- 渠道新增充值和内部导量充值直接汇总后台来源金额字段；运营表“自然新增总充值”尚未找到一致字段，不做替代映射。
- 人均观影时长：按观看人数加权，不平均每日均值。
- D1 留存：`sum(retainedUsers) / sum(newUsers)`。
- D3/D7/D30 留存：分别使用 `afterFirstData3/7/30.loginCnt`，仅对已经达到对应观察日的 cohort 执行 `sum(loginCnt) / sum(registerCount)`。
- 漏斗：各平台同名步骤先求和，再重新计算总转化率和步骤转化率。

## 运营日报口径边界

- 本轮新增 22 个可配置指标，均来自 `/api/admin/statistics/pDaySum` 的真实字段或同一行字段计算。
- 历史日期下的 MAU 尚无已确认稳定字段，暂不开放为日汇总指标。
- 访问、下载、注册转化及支付宝/微信拉单拆分不在当前已确认的 `pDaySum/getAllByRole` 字段中，继续保留为待接入，正式看板不生成替代值。

## 多平台规则

- 全部汇总：遍历 20 个有效 PID。
- 单平台：只请求一个 PID。
- 平台对比：最多 8 个 PID。
- 普通趋势和排行保留平台字段。
- 对比图为每个平台生成独立系列。
- 单个平台失败时保留其他平台结果，并在 `failedPlatforms` 中返回失败信息。
- 全部平台模式使用正式注册表中的 20 个平台作为固定集合；接口未返回的平台按 `0` 补齐并生成无数据提示。
- 平台排行、趋势、散点、日期热力、Cohort、瀑布和贡献矩形均保留所选范围内全部平台，不在转换层执行 Top N 截断。
- Cohort 使用“平台 × 注册日期”矩阵；平台趋势为每个平台生成独立日期系列。
- 搜索、内容等含二级业务维度的数据在卡片选择“平台”维度时，必须按 `platform` 聚合，不能用 `keyword/content/category` 替代平台轴。
- 分类、渠道和专项专用模板由前端按所选 PID 分别调用已有接口，再按对应业务维度汇总；页面范围必须与顶部筛选一致。

## 日期范围规则

- 快捷范围支持今日、近 7 日和近 30 日。
- 自定义范围使用 `YYYY-MM-DD` 起止日期，查询包含开始与结束当天。
- 全部通用卡片、下钻、渠道、内容分类和专项分析共用同一日期解析函数，避免页面口径不一致。
- 通用卡片分别请求当前周期和等长对比周期；未手动指定时，对比周期自动取当前周期之前紧邻的等长日期。
- 指标变化率为 `(当前值 - 对比值) / abs(对比值)`；对比值为零或缺失时不生成虚假变化率。

## 漏斗边界

- 内容漏斗：活跃用户、视频点击、视频播放、播放完成。
- 支付漏斗：VIP 点击、拉起支付、支付成功（内部事件 ID 仍为 `pre_pay`）。
- 当前数据来自同一日期区间的事件汇总计数。
- 不能证明同一批用户按顺序完成步骤。
- 当后一步独立事件量大于前一步时，标记为“事件口径不可比”，总转化率和步骤转化率显示“—”，不得展示超过 100% 的伪漏斗结论。
- 不支持用户级去重、任意转化窗口、页面/坑位/内容属性拆分。
- 桑基图与漏斗共用同一固定事件白名单和日期范围，必须明确标注“汇总近似，非用户级路径”。

## 视频内容口径

- 视频内容表现使用 `/api/admin/statistics/videoWatchRanking`，按平台筛选视频播放、点赞、收藏和收入。
- `/api/admin/statistics/todayVideos/getMany` 在当前后台返回旧平台 PID，不能作为现有 20 平台内容卡片的数据源。
- 视频排行接口没有观看人数和平均观看时长，因此这两项不在内容表现模型开放；人均观影时长继续由“观看深度”模型调用实时接口计算。
- 视频排行接口当前收入字段长期返回 0，因此系统内容模板默认只展示播放、点赞和收藏；收入字段仍保留在受控配置能力中，待上游确认有效后再恢复为默认卡片。

## 性能策略

- 上游 GET 请求相同 URL 并发合并。
- 成功响应在 BI 服务内存中缓存 60 秒。
- 缓存不写入数据库，服务重启后清空。
- 上游单请求默认 10 秒超时。
- 缓存只减少重复读取，不修改上游接口和数据。
- 前端对完全相同的分析请求共享 45 秒 Promise 缓存；失败立即清除，手动重试绕过缓存，单张卡片卸载不会取消其他共享请求。
- 平台排行通过动态高度展示全部平台；趋势图例可滚动，气泡矩阵仅限制常显标签数量但保留全部点位。
- 20 平台轴向 Tooltip 按值降序并使用双列完整列表，挂载到页面 `body`，避免被卡片裁切。
- 上游技术告警只进入查询诊断信息，不进入关键变化、主要原因等业务结论；业务结论仅由真实结果行计算。
# 2026-07-24 老用户广告与充值派生指标

- 老用户数：`max(0, DAU - 新增用户)`。
- 老用户广告点击人次/人数：总广告点击人次/人数减新增广告点击人次/人数。
- 老用户充值金额/人数：总充值金额/人数减新增充值金额/人数。
- 老用户广告率、付费率、ARPU、ARPPU 均使用区间 `sum(分子) / sum(分母)`，不平均每日比例。
- 数据源保持 `/api/admin/statistics/pDaySum`，未增加或修改上游请求。

## 查询缓存内存边界

- 浏览器查询共享缓存有效期 45 秒，最多保留 200 条；写入前清理过期项并淘汰最早项。
- BI 后端上游响应缓存有效期 60 秒，最多保留 500 条；写入前清理过期项并淘汰最早项。
- 两层缓存都只保存在进程内存，不持久化业务查询结果。
