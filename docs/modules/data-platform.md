## Token 与请求安全

- 上游当前不提供Token自动申请、续期或刷新能力；全部已登录角色完成维护二次认证后可人工轮换共享Token。日常查询由服务端自动使用已生效凭据，保存确认明确对全站查询生效。
- 主后台地址和用户名由服务器环境配置；初始`UPSTREAM_X_TOKEN`可选。未预置Token时服务仍以“数据源未配置”状态安全启动，由已登录用户进入维护页验证并保存首个Token。
- 当前生产平台注册表跨两个后台，因此第二后台地址与用户名必须成组配置；初始 `UPSTREAM_SECONDARY_X_TOKEN` 可选，不能脱离对应地址与用户名单独配置。这样第二站也可先启动维护入口，再人工录入首个 Token。
- 客户端按版本化平台目录中的 `siteId` 自动选择后台、Token 和匹配用户名；PID 与站点归属不再通过环境变量维护。未知或停用 PID 在发送网络请求前返回 `UPSTREAM_PID_NOT_AVAILABLE`，不允许默认落到站1。
- 任一查询缺少当前站点的有效 Token 时，服务端直接返回“数据源未配置”，不会发送不带 Token 的匿名上游请求。目录归属为站2但备用地址或用户名不完整时同样失败关闭，不允许静默回落主后台。
- 2026-07-21 使用 `pDaySum` 实测确认第二后台负责 `FBI、BZMH、TJS、BPS、HQW、TJD、MMV、AF、TFKJ、JRTT、YQ`；其余平台走主后台。`PH` 两侧均有数据，固定走主后台。
- 两个后台均通过 `x-token` 和 `name` 请求头认证，Token 与用户名必须来自同一登录会话。
- 前端“数据源维护”只允许更新站1/站2 Token；地址和用户名由后端运行环境管理，本地联调使用忽略的`.env.backend-local`；平台/PID/站点归属由版本化服务端目录管理。
- 后端 `/api/bi/admin/data-sources/test` 支持传入候选 Token 进行非保存验证；经典版 UI 仍只暴露“测试当前连接”和“验证并保存”，V2 `/admin/data-sources` 已补“仅验证新 Token”入口，并允许对尚未保存首个 Token 的已配置站点执行验证与保存；仍待生产安全门禁。
- 更新后的Token保存到仅服务进程所属账号可读写的私有文件（0600；生产专用账号为`ypbi`），优先级高于后端环境初始Token；接口永不回传原文。本地凭据文件与线上文件完全隔离。
- Token 是不透明字符串，无法从本地解析过期时间。
- 上游 HTTP 401/403 及业务码 `2002` 会映射为认证失败或 IP 白名单限制。
- VPS 的 IPv6 出口为 `2a02:4780:5e:fe72::1`，未授权时上游会拒绝；生产请求优先使用已加入白名单的 IPv4。
- BI 只调用已登记接口；分析链路当前使用读取请求，不修改原后台数据。
- 文档和日志不得输出 Token。

## M016 可复核验数流程（2026-09-09）

正式业务值只能来自已登记的上游 API，或输入、公式和版本均已登记的服务端加工服务；浏览器、本地配置、Markdown、验数文件和返回行最大日期都不是业务值或完整性状态的数据源。能力缺失时返回明确不可用状态，不用 0、旧值或本地推算补齐。

M016 的 `pDaySum.loginUserCount` 目前只是候选映射，注册表仍为 `not_started`，不能进入普通用户正式分析。仓库提供离线工具 `tools/validate-m016.mjs`，把验数分成三步：

1. `npm run validation:m016` 读取当前指标映射与平台目录，输出必须覆盖的全部启用 PID、版本和九项检查；该命令明确不联网、不修改注册表。
2. 维护者在受保护环境采集每个启用 PID、同一范围的 M016 技术查询响应，保存为 JSON 数组，使用 `npm run validation:m016:candidate -- --responses <响应数组文件> --output <新候选文件>` 生成 `controlled_technical_query` 候选。工具复用公共查询 Schema，核对当前权威 / 映射版本、来源接口、完整 PID 覆盖及各响应采集时间；真实 0 保留，`no_value` 转为 null，`no_record` 保持缺行。产物不含请求头、query ID、告警或水位，不转换为运行时业务源；仅写显式指定的 0600 新文件，不覆盖旧文件、不在终端输出逐行值、不联网或修改准入。独立参考须来自 `independent_sql` 或 `approved_export`，不能用同接口二次请求替代；文件不提交凭据或用户标识。
3. 先用 `node tools/validate-m016.mjs --check-reference <参考文件>` 预检参考范围，再用 `node tools/validate-m016.mjs --candidate <候选文件> --reference <参考文件>` 比较。输出只含版本、覆盖、产物标识、行数、SHA-256 和检查计数，不含逐行业务值。

自动检查覆盖平台范围、连续业务日、行契约、真实 0 / 空值和参考值一致性；全部通过也只能得到 `pending_review`。业务定义、Asia/Shanghai 日期边界、测试/机器人等排除规则、数据水位与补数必须人工复核。最终结果态证据只能放在 `server/v2/validation/evidence/`，并绑定当前指标权威版本、映射版本、平台目录 revision 及内容摘要、全部启用 PID、7～366 个连续完整业务日、候选 / 参考数据摘要、比较产物路径与摘要及九项结果；注册表通过 `evidenceSha256` 再固定证据原文。候选和参考数据的生成时间必须在覆盖期完整结束后且不晚于验数时间，验数时间最多容忍 5 分钟未来时钟偏差。缺失、路径逃逸、符号链接、范围或状态不一致会使指标快照生成与构建失败。

指标生成器同时写出 `server/v2/generated/metric-release-attestation.json`，服务启动时对指标快照、映射注册表、平台目录、结果态证据和自动比较产物重算哈希并核对一一对应关系；任一漂移则启动失败关闭。该产物只是仓库内一致性准入证明，不是带外签名。当前仓库没有 M016 通过证据，注册状态仍为 `not_started`；聊天中曾出现的 Token 未被工具使用或保存。

M016 的数据接口 `pDaySum` 当前没有经确认的完整日字段，也没有已登记的完成状态 API（上游或服务端加工），因此生产 Adapter 不从 `sumDate` 最大值、`total`、请求时间或其他未确认字段推断水位，固定返回 `watermark=null`。公共查询契约已经兼容结构化水位；未来只有在上游业务 API 明确返回完整日，或接入独立完成状态 API，并在 `server/v2/metric-watermark-source-registry.ts` 按 `metricId + sourceKind + sourceApiId` 完整登记后，Adapter 才可输出对应对象。验数通过但水位为空、来源未登记或三项不匹配时，正式查询继续失败关闭。
