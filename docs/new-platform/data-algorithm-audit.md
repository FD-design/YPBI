# NewAV 数据与算法审计

> 审计日期：2026-08-26。范围：真实 API、服务端 Adapter、跨日聚合、模板能力、图表转换、下钻与导出。

## 结论

- 5 个模板、23 张卡片、当前 30 天与对比 30 天共 46 次真实分析查询全部成功，无空结果或 500。
- 访问注册率、播放成功率、广告 CTR 使用 `sum(分子) / sum(分母)`，不再平均每日百分比。
- `rechargeTotal` 经真实序列验证为累计快照，周期值取日期最大的结束日；`rechargeNew` 才跨日求和。
- D1/D3/D7 只有比例、没有 cohort 分母，因此区间值为非空日期简单平均；未成熟日期保持空值，不能宣称加权留存。
- `cardBuy` 是购卡单数，不是去重付费人数；全站周期不再计算“付费率”。渠道 `vipBuyers / newUsers` 单独命名为渠道新增购卡率。
- `androidUv`、`iosUv` 是访问 UV，前端统一改为 Android/iOS 日均访问 UV，不再称为端别 DAU。

## 聚合口径

| 类型 | 指标 | 算法 |
|---|---|---|
| 日均 | DAU、日均观影人数、Android/iOS 日均访问 UV | `sum(日值) / 有数据自然日数` |
| 累计 | 新增注册、活跃人天、观影人天、购卡单数、播放成功/失败次数、广告点击 | 跨日求和 |
| 加权比例 | 访问注册率、播放成功率、广告 CTR、渠道新增购卡率 | `sum(分子) / sum(分母)` |
| 周期末快照 | 累计充值总额 | `max(date)` 对应的 `rechargeTotal` |
| 非空平均 | D1/D3/D7 留存 | `avg(non-null retentionDx)` |
| 当前快照 | 当前活跃 VIP、订单总数 | 只展示当前值，不做历史周期涨跌 |
| 不可计算 | D30、全站去重付费率、用户级漏斗 | 显示空值或明确限制，不使用 0/Mock 补齐 |

## 真实数据复算

抽查区间 `2026-07-27` 至 `2026-08-25`：

- 30 行自然日数据；DAU 日均 `296.3`，累计活跃人天 `8,889`。
- 访问注册率 `0.023940109879807242`，与原始 `sum(registNew) / sum(ipUniq)` 完全一致。
- 播放成功率 `0.749299935853153`，与原始 `sum(playOk) / sum(playOk + playErr)` 完全一致。
- D1 非空平均 `0.26066666666666666`；D3 有 2 个空值，D7 有 6 个空值，均未按 0 参与。
- 周期末 `rechargeTotal=3590`；返回行中无 `__` 内部计算字段泄漏。

## 修复项

1. 修复跨日比例简单平均。
2. 修复累计充值依赖接口返回顺序取值。
3. 缺失字段由错误的 0 改为空值。
4. 修复诊断卡把不同日期误当成不同平台排行。
5. 留存折线缺失点改为断点，不绘制伪造的 0。
6. 移除下钻抽屉固定数组演示折线和旧平台明细接口。
7. 看板导出改为重新查询真实 API，不再导出 Mock 数据。
8. 卡片库示例明确标注为结构预览。
9. NewAV 能力表替换旧平台 API 路径，23 张内置卡片全部通过能力校验。
10. 独立汇总漏斗增加强制警告，不能解释为同用户有序转化。

## 性能回归

- 46/46 次模板查询成功。
- 首次 30 天渠道查询约 24.8 秒，广告查询约 9.4 秒；均低于 60 秒上游超时。
- 相同数据集的后续卡片使用共享请求和短时缓存，留存当前期/对比期各 30 行。

## 仍需业务确认

- 金额显示单位仍需产品或后端确认；当前按接口原值展示。
- 留存字段对应的 cohort 定义和分母需上游文档确认；确认前只称“每日留存率”。
- `vipBuyers` 是否为渠道日去重买家数需后端确认；确认前不扩展为全站付费人数。
- overview 的 `activeVips`、`orders` 为当前快照，接口不支持历史回放。
